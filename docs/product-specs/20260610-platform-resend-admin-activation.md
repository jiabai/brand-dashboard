# 平台重发租户管理员激活邮件

> 状态：待实现，2026-06-10
>
> 本文档定义平台管理员对「待激活」租户管理员重新签发激活令牌并重发激活邮件的产品流程、边界和验收标准。它补充 `docs/product-specs/20260603-000000-admin-activation-email.md` 的创建时邮件发送流程，解决激活令牌 7 天过期后无补救路径的问题。

## 1. 背景

平台创建租户时为首个租户管理员生成 7 天有效的激活令牌，并通过 SMTP 发送激活邮件（保留人工兜底）。若管理员未在 7 天内完成激活，令牌过期后激活接口返回「令牌已过期」，账号停留在 `pending_activation` 且无法登录。当前系统没有产品化补救路径：没有重发接口、没有令牌重签机制，激活链接也只在创建租户时出现一次，只能由运维手工签发令牌或直接修改数据库。

平台租户列表与详情页已展示管理员「待激活」状态，运营具备发现问题的能力；本阶段补齐对应的补救操作入口：在平台租户详情页提供「重发激活邮件」，重新签发激活令牌并复用既有邮件发送与人工兜底机制。

## 2. 目标

1. 平台管理员在 `/platform/tenants/:tenantKey` 的租户管理员卡片，对「待激活」管理员触发重发激活邮件。
2. 后端重新签发 7 天有效的激活令牌，复用既有邮件模板与 SMTP 发送逻辑。
3. 接口响应返回新的激活链接与邮件发送状态；SMTP 未配置或发送失败时仍返回激活链接供人工兜底。
4. 重发目标与详情页展示的管理员一致：`user_tenants` 中 `role='admin'` 按 `created_at` 最早的成员。
5. 仅 `pending_activation` 状态的管理员可重发；已激活或状态异常的账号明确拒绝。

## 3. 非目标

1. 不支持修改管理员邮箱；创建时邮箱填错的纠正流程未来单独立项。
2. 不提供租户管理员自助重发（公共接口）；本阶段仅平台侧运营操作。
3. 不在租户列表新增筛选或超期警示；列表与详情已有「待激活」状态展示。
4. 不保存激活邮件发送历史；只返回本次重发结果。
5. 不改变激活令牌生成与校验规则（仍为 7 天有效、HMAC 签名、激活后失效）。
6. 不主动作废历史令牌；并存窗口的风险评估见安全要求。
7. 不引入邮件队列、重试任务或频率限制。

## 4. 用户流程

### 4.1 重发成功

1. 平台管理员在 `/platform/tenants` 列表发现某租户管理员状态为「待激活」。
2. 进入租户详情页，租户管理员卡片显示「重发激活邮件」按钮。
3. 点击按钮，后端重新签发激活令牌并发送激活邮件。
4. 页面展示「激活邮件已发送」及新的激活链接（可复制）。
5. 租户管理员收到邮件，打开 `/activate?token=...` 设置密码完成激活。
6. 激活后详情页管理员状态变为「已激活」，重发按钮不再显示。

### 4.2 SMTP 未配置或发送失败

1. 平台管理员点击「重发激活邮件」。
2. 后端签发新令牌，但邮件未发送成功（SMTP 未配置或发送失败）。
3. 接口仍返回成功，`emailDelivery.status` 为 `not_configured` / `failed`。
4. 页面展示人工兜底提示，平台管理员复制新激活链接人工发送。

### 4.3 不可重发场景

1. 管理员已激活：按钮不显示；直接调用接口返回 400「账号已激活」。
2. 租户无 admin 成员：接口返回 400「该租户未设置管理员」，运营改用应急设置入口（见 `20260610-platform-tenant-admin-emergency-entry.md`）。
3. 管理员状态为 `inactive` / `suspended`：接口返回 400「账号状态异常」。

## 5. API 行为

`POST /api/v1/platform/tenants/{tenant_key}/resend-activation`

- 权限：`platform_admin`（复用 `require_platform_admin`）。
- 行为：按详情页同款规则定位首个 admin 成员（`role='admin'` 按 `created_at ASC` 取第一条），校验账号状态后重新签发 7 天激活令牌，在事务外发送激活邮件。本接口不写数据库。
- 成功响应（200）：

```json
{
  "status": "success",
  "code": 200,
  "message": "激活令牌已重新签发",
  "data": {
    "tenantKey": "tn_1a2b3c4d5e6f",
    "tenantName": "示例企业",
    "adminEmail": "admin@example.com",
    "activationUrl": "https://example.com/activate?token=...",
    "loginUrl": "https://example.com/login",
    "emailDelivery": {
      "status": "sent",
      "to": "admin@example.com",
      "message": "激活邮件已发送"
    }
  }
}
```

- `emailDelivery.status` 取值与含义沿用创建租户接口：`sent` / `not_configured` / `failed`；后两者不改变接口成功语义。
- 错误响应：

| 场景 | 状态码 | message |
|---|---|---|
| 租户不存在 | 404 | 租户不存在 |
| 租户无 admin 成员 | 400 | 该租户未设置管理员 |
| 管理员已激活 | 400 | 账号已激活 |
| 管理员状态异常（inactive/suspended） | 400 | 账号状态异常 |
| 非平台管理员调用 | 401/403 | 沿用现有平台权限拒绝语义 |

## 6. 页面行为

- 租户管理员卡片在 `adminStatus = pending_activation` 时显示「重发激活邮件」按钮，与「应急设置」按钮并列；其他状态不显示。
- 点击后按钮进入 loading 态；不弹确认框（操作不破坏数据）。
- 重发成功后在卡片内展示结果区：邮件发送状态文案 + 新激活链接（可复制），交互与创建租户结果面板一致。
- `not_configured` / `failed` 时展示「请复制激活链接人工发送」类兜底提示。
- 接口返回 4xx 时展示错误信息，不展示激活链接。

## 7. 安全要求

1. 仅平台管理员可调用重发接口；非平台用户拒绝访问。
2. 新激活链接只出现在本次接口响应和激活邮件中；租户列表与详情接口继续不返回激活令牌。
3. 激活令牌规则不变：7 天有效、HMAC 签名、激活成功后账号转 `active`，所有未使用令牌随之失效（激活接口拒绝已激活账号）。
4. 已知并存窗口：历史未过期令牌无法主动作废，7 天内重复重发会短暂并存多个有效令牌；任一令牌完成激活后其余令牌全部失效，风险可接受，无需令牌版本化。
5. 响应、日志不得输出 `SMTP_PASSWORD`、SMTP 异常堆栈或内部网络细节。
6. 邮件发送发生在令牌签发之后，不涉及数据库事务；发送失败不影响接口成功语义。

## 8. 验收标准

- 平台管理员对「待激活」管理员重发后，管理员邮箱收到包含新激活链接的邮件，新链接 7 天内可完成激活。
- 旧令牌已过期时，新令牌仍可正常激活账号。
- 已激活租户：详情页不显示重发按钮，直接调用接口返回「账号已激活」。
- 无 admin 成员的租户：接口返回「该租户未设置管理员」。
- 非平台用户调用接口被拒绝。
- SMTP 未配置/发送失败时接口仍返回 200，响应含 `emailDelivery.status` 与新激活链接，页面展示人工兜底提示。
- 平台租户列表与详情接口不返回激活令牌、`SMTP_PASSWORD` 或 SMTP 错误细节。
- 后端重发服务与路由、前端按钮与结果展示有自动化测试覆盖。
- `ruff check api`、后端 pytest、前端测试、`npm --prefix web run build`、`python scripts/validate_agents_docs.py --level ERROR` 全部通过。
