# 管理员激活邮件发送规格

> 状态：待实现，2026-06-03
>
> 本文档定义平台创建租户后，通过 SMTP 自动发送首个租户管理员激活邮件的产品流程、边界和验收标准。它补充 `docs/product-specs/20260520-010000-platform-operations-console.md` 中“创建成功后人工发送激活链接”的 MVP 流程。

## 1. 背景

当前平台管理员在 `/platform/tenants` 创建租户后，系统只在创建结果面板展示管理员激活链接和邀请码。平台操作员需要手动复制激活链接并发给客户管理员。该流程可用，但容易漏发、复制错误或无法追踪邮件是否尝试发送。

本阶段引入 SMTP 配置，让系统在租户创建成功后自动向首个租户管理员邮箱发送激活邮件，同时保留页面展示激活链接作为人工兜底。

## 2. 目标

1. 支持通过 `api/.env` 配置 SMTP 服务：
   - `SMTP_HOST`
   - `SMTP_PORT`
   - `SMTP_USERNAME`
   - `SMTP_PASSWORD`
   - `SMTP_FROM`
   - `SMTP_USE_TLS`
2. 平台管理员创建租户成功后，后端自动发送管理员激活邮件。
3. 邮件内容包含租户名称、管理员邮箱、激活链接、有效期提示和安全提示。
4. 邮件发送不参与租户创建数据库事务；SMTP 失败不得回滚租户创建。
5. 创建租户响应返回邮件发送状态，前端展示“已发送 / 未配置 / 发送失败”。
6. 即使邮件未发送，平台后台仍展示激活链接，方便平台操作员人工发送。
7. 租户管理员打开 `/activate?token=...` 时，前端自动填入激活令牌。

## 3. 非目标

1. 不接入第三方邮件服务商 API；本阶段只使用标准 SMTP。
2. 不新增邮件队列、重试任务或异步 worker。
3. 不实现邮件模板后台、品牌化模板编辑或多语言模板。
4. 不保存激活邮件发送历史；只返回本次创建租户的发送结果。
5. 不改变激活 token 的生成和校验规则。

## 4. 用户流程

### 4.1 SMTP 已配置且发送成功

1. 平台管理员登录 `/platform/tenants`。
2. 平台管理员提交创建租户表单。
3. 后端创建租户、管理员用户、租户成员关系、邀请码和激活链接。
4. 后端读取 SMTP 配置，向管理员邮箱发送激活邮件。
5. 前端创建结果面板展示激活链接、邀请码、登录地址，并提示“激活邮件已发送”。
6. 租户管理员收到邮件后打开激活链接，激活页自动填入令牌。
7. 租户管理员设置密码并登录。

### 4.2 SMTP 未配置

1. 平台管理员创建租户成功。
2. 后端发现 SMTP 必填项不完整，不尝试发送邮件。
3. 前端展示“SMTP 未配置，请复制激活链接人工发送”。
4. 平台管理员人工发送激活链接给客户管理员。

### 4.3 SMTP 发送失败

1. 平台管理员创建租户成功。
2. 后端尝试发送邮件失败。
3. 后端响应仍为租户创建成功，并返回 `emailDelivery.status = "failed"`。
4. 前端展示“邮件发送失败，请复制激活链接人工发送”。

## 5. API 行为

`POST /api/v1/platform/tenants` 成功响应新增：

```json
{
  "data": {
    "tenantKey": "tn_1a2b3c4d5e6f",
    "adminEmail": "admin@example.com",
    "activationUrl": "https://example.com/activate?token=...",
    "inviteCode": "ABC123",
    "emailDelivery": {
      "status": "sent",
      "to": "admin@example.com",
      "message": "激活邮件已发送"
    }
  }
}
```

`emailDelivery.status` 取值：

| status | 含义 | 前端行为 |
|---|---|---|
| `sent` | SMTP 已配置且发送成功 | 提示邮件已发送 |
| `not_configured` | SMTP 配置不完整 | 提示人工发送激活链接 |
| `failed` | SMTP 连接、认证或发送失败 | 提示人工发送激活链接 |

## 6. 安全要求

1. `.env` 不提交到 Git；只允许在文档中写变量名和占位符，不写真实授权码。
2. 后端不得在日志、错误响应或邮件发送状态中输出 `SMTP_PASSWORD`。
3. 邮件发送失败响应不得包含 SMTP 异常堆栈、邮箱授权码或内部网络细节。
4. 激活链接仍只在创建租户成功响应和邮件中出现；租户列表接口继续不得返回 activation token。
5. 激活 token 保持 7 天有效、一次性使用、重复激活失败。
6. 邮件发送必须发生在租户创建事务提交之后，避免邮件发出但租户未创建成功。

## 7. 验收标准

- 配置 SMTP 后，创建租户会调用 SMTP 并向管理员邮箱发送包含激活链接的邮件。
- 管理员打开邮件中的 `/activate?token=...` 后，激活页自动填入令牌。
- 未配置 SMTP 时，创建租户仍成功，响应包含 `emailDelivery.status = "not_configured"`。
- SMTP 发送失败时，创建租户仍成功，响应包含 `emailDelivery.status = "failed"`。
- 前端创建结果面板展示邮件发送状态和人工兜底提示。
- 平台租户列表不返回 `activationToken`、`activationUrl`、`SMTP_PASSWORD` 或 SMTP 错误细节。
- 后端邮件服务和路由集成有自动化测试覆盖。
- `pytest api/tests/test_email_sender.py api/tests/test_auth.py -q`、相关前端测试、构建和文档验证通过。
