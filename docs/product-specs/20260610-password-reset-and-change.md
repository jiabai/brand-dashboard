# 自助密码重置与修改密码

> 状态：待实现，2026-06-10
>
> 本文档定义租户用户（含租户管理员）忘记密码后的自助邮件重置流程，以及已登录用户的修改密码能力。它补齐当前系统完全缺失的密码找回路径：登录页无入口、无公开重置接口、账户管理页无修改密码功能，唯一重置能力是平台管理员 bootstrap CLI（不适用于租户用户）。

## 1. 背景

租户管理员或成员忘记密码后，当前唯一办法是运维直接修改数据库 `password_hash`。激活流程不能复用为重置：激活接口拒绝已激活账号，重发激活邮件仅对 `pending_activation` 生效。多份平台规格确认了「平台不重置密码」的只读边界，因此补救必须走自助路径。

本阶段提供两条产品化路径：

1. **忘记密码（未登录）**：登录页申请重置邮件，凭邮件中的一次性链接设置新密码。
2. **修改密码（已登录）**：账户管理页验证当前密码后设置新密码。

## 2. 目标

1. 登录页提供「忘记密码」入口；`/reset-password?token=...` 打开重置表单并自动填入令牌。
2. 重置令牌复用 `sign_token/verify_token`：`type=password_reset`，有效期 1 小时，payload 携带当前 `password_hash` 的指纹（SHA-256 hexdigest 前 16 个十六进制字符）。
3. 一次性语义：校验时重算当前密码哈希指纹并比对，密码一旦变更（无论经重置还是修改），所有未使用的重置令牌全部失效。
4. 重置邮件复用既有 SMTP 基建与配置；邮件包含重置链接与 1 小时有效期提示。
5. 防枚举：忘记密码接口对「邮箱不存在 / 账号非 active / 冷却期内 / 发送成功 / 发送失败」返回完全一致的响应。
6. 滥用防护：忘记密码接口按邮箱做进程内存级 60 秒冷却。
7. 已登录用户在 `/accounts/:tenantKey` 验证当前密码后修改密码。
8. 修复登录页现存缺陷：`?token=` 自动填充改为路由感知，`/activate` 与 `/reset-password` 各自填充对应表单，互不劫持。

## 3. 非目标

1. 不升级密码强度策略；沿用现有最小 8 位约束。
2. 不实现密码历史、密码过期或定期改密策略。
3. 不持久化重置令牌（无新表）；一次性语义由密码哈希指纹实现。
4. 不实现「改密码后失效已签发 JWT」；见安全要求中的已知局限。
5. 不做短信或其他通道的重置。
6. 不做平台侧代发重置邮件（原方案 B，单独立项需先推翻平台只读边界）。
7. 除 60 秒冷却外不引入通用限流框架；两个新公开端点纳入 `docs/SECURITY.md` 的上线前限流计划清单。

## 4. 用户流程

### 4.1 忘记密码重置成功

1. 用户在 `/login` 点击登录表单下方「忘记密码？」，切换到「重置」标签。
2. 输入邮箱提交，页面提示「如果该邮箱已注册并激活，重置邮件已发送」。
3. 用户收到邮件，打开 `/reset-password?token=...`，重置表单自动填入令牌。
4. 输入新密码与确认密码提交，提示「密码已重置」，切回登录标签。
5. 用户用新密码登录成功；旧密码与所有旧重置令牌失效。

### 4.2 邮箱不存在、账号未激活或被停用

1. 用户提交任意邮箱。
2. 后端静默跳过发送（不存在 / `pending_activation` / `inactive` / `suspended` 均不发信）。
3. 响应与 4.1 第 2 步完全一致，不暴露账号是否存在及其状态。

### 4.3 令牌失效场景

1. 超过 1 小时：提交重置返回 400「重置链接无效或已失效」。
2. 已使用过（密码已变更）：同上，统一文案。
3. 用激活令牌提交重置（或反之）：类型不匹配，拒绝。
4. 用户可回到「重置」标签重新申请邮件。

### 4.4 已登录修改密码

1. 用户进入 `/accounts/:tenantKey` 的「修改密码」卡片。
2. 输入当前密码、新密码、确认密码提交。
3. 当前密码错误返回 400「当前密码错误」；成功提示「密码已修改」。
4. 修改成功后既有登录态保持有效（见已知局限），后续登录使用新密码。

## 5. API 行为

### 5.1 `POST /api/v1/public/auth/forgot-password`

- 入参：`{"email": "user@example.com"}`（Pydantic 校验非空）。
- 行为：查找 `status='active'` 的用户；命中且不在冷却期则签发 1 小时重置令牌并发送重置邮件；其余情况静默跳过。按邮箱记录 60 秒冷却（进程内存）。
- 响应（**所有路径一致**，含 SMTP 未配置/发送失败）：

```json
{
  "status": "success",
  "code": 200,
  "message": "如果该邮箱已注册并激活，重置邮件已发送",
  "data": null
}
```

- 响应不得包含 `emailDelivery`、令牌、链接或任何随账号状态变化的字段。

### 5.2 `POST /api/v1/public/auth/reset-password`

- 入参：`{"token": "...", "password": "...", "confirmPassword": "..."}`（密码最小 8 位；两次不一致返回 400「两次密码不一致」）。
- 行为：`verify_token` 校验签名与有效期 → 校验 `type == "password_reset"` → 重算用户当前 `password_hash` 指纹并与 payload 比对 → 更新 `password_hash` 与 `updated_at`。
- 成功响应：`{"status":"success","code":200,"message":"密码已重置","data":null}`。
- 错误响应（统一信封 `{"status":"error","message",...,"code":400}`）：

| 场景 | message |
|---|---|
| 签名无效 / 非 password_reset 类型 / 用户不存在 / 指纹不匹配 | 重置链接无效或已失效 |
| 令牌过期 | 重置链接无效或已失效 |
| 两次密码不一致 | 两次密码不一致 |

注：内部区分原因仅用于测试断言；对外文案统一，不区分「过期」与「已使用」，避免泄露令牌状态。

### 5.3 `POST /api/v1/auth/change-password`

- 认证：`get_current_user`（Bearer JWT），未认证 401。
- 入参：`{"currentPassword": "...", "newPassword": "...", "confirmPassword": "..."}`（新密码最小 8 位）。
- 行为：校验当前密码（`verify_password`）→ 更新 `password_hash` 与 `updated_at`。
- 成功：`{"status":"success","code":200,"message":"密码已修改","data":null}`。
- 错误：当前密码错误 → 400「当前密码错误」；两次不一致 → 400「两次密码不一致」。

### 5.4 重置邮件

- `email_sender.py` 新增 `send_password_reset_email`，复用 `SmtpConfig` 与发送逻辑。
- 邮件包含：收件邮箱、重置链接（`{base_url}/reset-password?token=...`，base url 一律使用平台默认域 `AUTH_BASE_URL`，即 `_build_tenant_base_url(None)`；重置是账号级操作，不绑定租户子域）、「1 小时内有效」提示、「非本人操作请忽略」提示。
- 邮件发送失败不改变接口响应（见 5.1）；失败仅体现在服务端可观测层面，不落令牌、不落密码。

## 6. 页面行为

### 6.1 登录页（LoginView）

- 标签栏从 3 列改 4 列：登录 / 激活 / 注册 / 重置。
- 登录表单下方新增「忘记密码？」链接，点击切换到「重置」标签。
- 「重置」标签含两个表单（同注册标签「一页两表单」模式）：
  1. 申请表单：邮箱 → 「发送重置邮件」，成功提示统一文案；
  2. 重置表单：令牌 + 新密码 + 确认密码 → 「重置密码」，成功后切回登录标签并提示用新密码登录。
- 路由：`App.jsx` 新增 `/reset-password` → `LoginView defaultTab="reset"`。
- 令牌自动填充改为路由感知：`/activate?token=...` 只填激活表单并切激活标签；`/reset-password?token=...` 只填重置表单并切重置标签。两者互不触发。

### 6.2 账户管理页（AccountManagement）

- 新增「修改密码」卡片：当前密码、新密码、确认密码三个字段，提交按钮复用现有 `handleOperation` 工厂与反馈区。
- 前端先校验两次新密码一致再调接口；错误信息展示接口返回 message。

### 6.3 API 适配器

`web/src/api/auth.js` 新增 `forgotPassword`、`resetPassword`（public，POST）与 `changePassword`（带认证头，POST）。

## 7. 安全要求

1. 防枚举三处一致：5.1 响应全路径统一；非 active 账号静默跳过；冷却期内同样返回统一成功文案。与 `docs/SECURITY.md`「登录失败统一错误」原则对齐。
2. 重置令牌只出现在重置邮件中；任何接口响应、日志不得输出令牌、重置链接、`SMTP_PASSWORD` 或 SMTP 异常细节。
3. 令牌类型严格隔离：`password_reset` 令牌不能用于激活，`activation` 令牌不能用于重置。
4. 一次性失效链：重置或修改密码成功后 `password_hash` 变更，所有存量重置令牌因指纹不匹配而失效；重复使用同一令牌必然失败。
5. 忘记密码接口按邮箱 60 秒冷却（进程内存实现，重启即清空，可接受）；两个新公开端点写入 `docs/SECURITY.md` 限流计划清单。
6. 修改密码必须验证当前密码，不得仅凭登录态直接改密。
7. **已知局限**：重置/修改密码不会失效已签发的 access token（无状态 JWT 仅含 user_id 与 exp）。「改密码踢出所有会话」需令牌版本化（JWT 携带密码指纹并在认证依赖中比对），列为未来增强，本期不做。
8. 密码一律经 `hash_password` 入库；接口与日志不出现明文密码。

## 8. 验收标准

- 活跃用户申请重置后收到含链接的邮件，1 小时内可经 `/reset-password?token=...` 设置新密码并用新密码登录。
- 旧密码在重置成功后立即失效；同一重置令牌第二次使用被拒绝；重置后再用更早签发的重置令牌也被拒绝。
- 激活令牌提交到重置接口被拒绝；重置令牌提交到激活接口被拒绝。
- 对不存在邮箱、`pending_activation`/`inactive`/`suspended` 账号、冷却期内重复申请，忘记密码接口的 HTTP 状态码与响应体与成功路径完全一致，且不发送邮件。
- 已登录用户提供正确当前密码可修改密码；当前密码错误返回「当前密码错误」；未认证调用修改密码接口返回 401。
- `/activate?token=...` 与 `/reset-password?token=...` 各自填充对应表单，互不劫持。
- 登录页存在「忘记密码」入口与「重置」标签；账户管理页存在「修改密码」卡片。
- 接口响应与日志不含令牌、明文密码、SMTP 凭据或异常堆栈。
- 后端重置/修改密码仓储与路由、前端适配器与页面契约有自动化测试覆盖。
- `ruff check api`、后端 pytest、前端测试、`npm --prefix web run build`、`python scripts/validate_agents_docs.py --level ERROR` 全部通过。
