# 租户加入团队入口边界规格

> 状态：执行中，2026-06-09

## 背景

项目工作台侧边栏此前展示“监测项目”和“账户管理”。其中“账户管理”页面实际承载的是邀请码核验、员工注册、登录辅助，以及一个已迁移到平台后台的租户开通提示。进入客户项目工作台后，这个入口容易让租户用户误以为可以管理成员，也容易让平台管理员只读客户视角误入租户注册流程。

## 目标

1. 平台管理员通过只读旁路进入客户项目工作台时，不展示租户侧加入/账户入口。
2. 租户成员仍可通过侧边栏进入一个清晰的“加入团队”页面。
3. 登录后的租户侧页面不再承载公开登录表单。
4. 现有页面在完整成员管理未实现前，只保留邀请码核验和员工注册能力。

## 非目标

1. 不实现成员列表、角色修改、邀请码生成或邀请码管理。
2. 不新增后端 API。
3. 不改变公开登录页、激活页或平台注册流程。
4. 不改变平台后台 `/platform/*` 的租户管理能力。

## 前端行为

- 租户成员侧边栏主入口显示为“加入团队”。
- `/accounts/:tenantKey` 页面标题显示“加入团队与邀请注册”。
- 页面只保留“员工注册”流程，其中包含邀请码核验和注册表单。
- 页面不再展示“账户登录”tab，也不调用公开登录 API。
- 页面不再展示“租户开通”tab；平台租户开通继续只在平台后台执行。
- 当当前登录账号具备 `platform_admin` 角色并进入租户项目工作台时，侧边栏隐藏“加入团队”入口；该规则不因历史租户 membership 放开。

## 验收标准

- 平台只读客户视角下侧边栏只显示“监测项目”。
- 普通租户成员侧边栏显示“监测项目”和“加入团队”。
- `/accounts/:tenantKey` 不包含登录表单或 `loginApi` 调用。
- 路由仍保持 `/accounts/:tenantKey`，避免破坏历史链接。
- 前端测试、构建和文档验证通过。
