# 仪表板 UI 视觉优化

## 背景

Web UI 已完成 shadcn/ui 技术迁移，但当前视觉表现仍停留在“组件可用”阶段：暗紫背景过重、空状态占位过大、卡片和顶部筛选层级松散，整体不符合运营型品牌仪表板的专业感和扫描效率。

`DESIGN-TOKENS.md` 提供了一套暖色编辑感设计参考：cream canvas、warm ink、coral primary、dark product surface、低阴影和清晰圆角层级。本轮目标是将该风格转换为适合 Brand Dashboard 的业务界面，而不是照搬营销页的大字号、大留白和 hero 结构。

## 用户价值

优化完成后，用户打开仪表板时能够更快判断当前任务、时间范围、品牌排名、平台表现和引用详情。界面应更可信、更安静、更适合长时间查看，同时保留 shadcn/ui 迁移后的源码可控性。

## 目标

1. 建立 Brand Dashboard 专属的暖色运营仪表板视觉方向。
2. 将全局主题从当前深紫临时主题调整为 warm canvas + warm ink + coral accent。
3. 优化 App shell、侧栏、顶部栏、筛选控件和内容卡片的信息层级。
4. 降低空状态视觉重量，让“暂无数据”不再主导整个页面。
5. 保持现有路由、API Adapter、时间筛选语义和数据契约不变。

## 非目标

1. 不修改后端 API、数据库和多租户隔离逻辑。
2. 不重新设计信息架构或新增业务页面。
3. 不引入新的 UI 组件库、图表库或全局状态管理。
4. 不改变 shadcn/ui 作为 UI 原语源码组件的方向。
5. 不照搬 `DESIGN-TOKENS.md` 的营销页 hero、footer、pricing、CTA band 等页面结构。

## 使用场景

1. 用户进入首页，能清楚看到当前任务、更新时间、时间筛选、品牌排名和核心指标区域。
2. 用户在没有数据或后端报错时，能识别状态但不会被大面积空卡片干扰。
3. 用户在侧栏切换页面时，当前页面位置和任务上下文保持清楚。
4. 用户在趋势、分平台、信源、情感、任务状态等页面查看数据时，卡片、表格和图表保持一致的视觉语言。
5. 用户在桌面和移动端访问时，顶部栏、侧栏和内容区域不会重叠或挤压文字。

## 功能要求

| 编号 | 要求 |
|------|------|
| FR-1 | 重定义 `web/src/index.css` 的 shadcn/Tailwind semantic tokens，使默认主题采用暖色浅色仪表板风格 |
| FR-2 | 优化 `DashboardLayout` 顶部栏的信息层级、间距、筛选控件和实时数据提示 |
| FR-3 | 优化 `Sidebar` 的品牌区、导航项、active 状态、分组间距和移动端显示 |
| FR-4 | 优化 `Card`、`Button`、`Badge`、`Table`、`EmptyState`、`LoadingSpinner` 等基础组件的视觉一致性 |
| FR-5 | 优化首页和各分析页的卡片密度、标题层级、空状态高度和内容排布 |
| FR-6 | 图表和指标颜色使用 warm ink、coral、teal、amber、success/error 语义色，不回到单一紫色体系 |
| FR-7 | 保持现有时间筛选、URL 参数、表单提交和 API 请求行为不变 |
| FR-8 | 增加或调整前端测试，覆盖主题入口、关键 class 约束或组件状态行为 |

## 非功能要求

| 类别 | 要求 |
|------|------|
| 可维护性 | 主题色优先通过 CSS variables 和 Tailwind semantic tokens 管理，不在业务组件散落 hex |
| 一致性 | 组件圆角、边框、背景、文字层级遵循 `docs/DESIGN.md` 的 UI 规范 |
| 可读性 | 主体文字对比度满足浅色背景可读性，按钮文字不依赖浏览器默认颜色 |
| 信息密度 | 仪表板默认视图应尽量在首屏展示核心内容，避免空状态或卡片占据过高空间 |
| 响应式 | 桌面侧栏、移动端导航、顶部筛选和表格容器不能出现重叠或文字溢出 |
| 性能 | 不因视觉优化引入明显更重的运行时依赖 |

## 设计约束

1. 基础风格参考 `DESIGN-TOKENS.md`，但以仪表板可用性优先。
2. Canvas 使用暖白或浅奶油色，不使用当前深紫作为全局页面底色。
3. Coral 只用于主操作、active 强调和少量状态提示，不大面积铺满业务卡片。
4. Dark surface 只用于局部高对比模块或侧栏，不作为全部内容区背景。
5. 仪表板卡片圆角默认不超过 8px，除非现有 shadcn 原语或特殊面板已有明确需求。
6. 页面不使用营销式 hero、不使用装饰性渐变球、不使用大段说明文案。

## 验收标准

1. `npm --prefix web test` 通过。
2. `npm --prefix web run build` 通过。
3. `python scripts/validate_agents_docs.py --level ERROR` 通过。
4. 浏览器验证桌面和移动端首页渲染：侧栏、顶部栏、筛选、卡片、空状态无重叠。
5. 首页首屏观感从深紫临时主题转为暖色运营仪表板主题。
6. 空状态视觉高度和文字层级明显降低，不再主导页面。
7. `rg -n "#[0-9a-fA-F]{3,8}" web/src` 检查新增硬编码色值，新增颜色应有合理例外或进入 token。
