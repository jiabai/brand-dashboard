# Core Beliefs

## 配置驱动优先

Brand Analysis 的主要变化点应在配置层表达。插件启用、数据源表、字段、输出目录和 LLM provider 参数都应从 `config/` 或环境变量读取，代码只保留稳定编排逻辑和输入验证。

## 插件边界稳定

新增分析能力时优先新增插件，而不是修改主流程。插件通过 `AnalysisPlugin` 暴露单条分析和批量聚合，编排层负责读取数据、批次分组、错误收敛和输出保存。

## 外部依赖可诊断

MySQL、LLM API、文件系统和环境变量都是外部边界。失败时必须有足够上下文定位问题，包括插件名、表名、provider、输出目录或配置路径，但不能泄露密钥。

## 数据形状先验证

表名、字段列表、CLI 参数、JSON 配置、日期格式和 LLM 响应都不能靠猜。进入核心流程前先校验，无法满足最低数据形状时返回明确错误或走记录过的降级路径。

## 规范跟代码同步

当插件合同、配置结构、数据库写入、CLI 行为、输出 JSON 或安全边界变化时，必须同步 `AGENTS.md`、`docs/ARCHITECTURE.md`、`docs/DESIGN.md`、`docs/SECURITY.md` 或对应产品规格。
