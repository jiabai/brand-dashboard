# Brand Analysis Core Capability

## 背景

团队需要批量分析品牌在 AI 问答或引用数据中的认知表现，包括品牌是否被提及、是否首位提及、引用链接状态、来源识别和 LLM 服务可用性。项目通过配置化数据源和插件体系支持不同分析维度。

## 目标

- 用户可以通过 CLI 指定品牌和配置文件，运行批量品牌分析。
- 用户可以在配置文件中启用或禁用插件，并为插件指定 MySQL 数据源和输出路径。
- 系统按数据生成日期分批处理，并将结果保存到插件专属输出目录。
- 核心插件可以在需要时调用统一 LLM 层，并支持 provider 配置和环境变量补全。
- 部分指标插件可以将结果同步写入 MySQL 业务表，支持后续统计。

## 非目标

- 不提供 Web UI 或交互式仪表盘。
- 不在默认测试中依赖真实 LLM Key 或真实生产数据库。
- 不把所有供应商 SDK 直接暴露给插件。
- 不保证任意数据库表都可分析，表需要满足插件所需字段或有可降级文本字段。

## 使用场景

- 品牌监测：按品牌、租户、任务批次、平台和日期窗口分析问答记录。
- 竞品对比：传入竞品列表，分析品牌和竞品在回答中的提及顺序。
- 引用评估：分析引用 URL 是否已发布、内容类型和可统计字段。
- 运行诊断：用工具插件检查 LLM 服务连通性或导入已有结果。

## 约束

- CLI 必须要求品牌名；配置缺失时可尝试默认配置。
- `brand_analysis.plugins` 是插件启用和数据源配置的唯一入口。
- 表名只允许字母、数字和下划线，字段名必须来自配置和数据库 inspector 的交集。
- 输出 JSON 必须可追溯到品牌、插件、分析时间和日期目录。
- API Key、数据库密码和敏感文本不得进入日志或公开文档。

## 验收标准

- `python -m src --help` 能显示 CLI 参数。
- 给定有效配置和可访问数据库时，`python -m src -b <品牌> -c <配置>` 能完成批量分析或返回可诊断错误。
- 启用的数据源插件按 `output/<plugin>/<YYYYMMDD>/` 保存结果。
- 配置错误、日期格式错误、插件失败或 LLM 配置缺失时有明确错误信息。
- 新增插件必须有离线测试或清晰的手动验证步骤。
